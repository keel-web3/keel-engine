# Original rollable robots

`createRobotGenome(seed, pins, families)` resolves one versioned plain JSON identity: named family, hull, face, shell grammar, limbs, material, livery and retracted gear. Each named-base selection and its within-base geometry uses an independent stable stream. Pins change only the named site. `robotAttributes` reports those same resolved parts for a future metadata consumer; this pack claims no NFT ownership, payment or publication.

Four original starter families provide distinct articulation and persistent shell signatures: Rivet Courier shoulder petals and offset visor; Iris Scout radial lens shell; Tortoise Hauler low quadruped clamshell and load cleats; Reed Skimmer long tripod ribs and split crown. `defineRobotFamily` admits additional named profiles within the current morphology/part grammar. New geometry grammars require a versioned registered implementation.

Generator revision3 clips face, hinge and retracted-gear marks onto the actual rendered shell facets with explicit material depth. The entire rolled mesh stays within unit radius. Robot2's exact native previews remain archived with its observed patch clipping and small-scale silhouette limitations; revised source admission alone does not establish native character readability.

Family IDs use the canonical entity grammar (lower-case letters, digits and dashes); a pack supplies its namespace. Discovery validates and copies each family before exposing its named choices. The public hull, face and gear registries list only bases with implemented geometry. Family-specific hoods, jaws, sensor crowns and hinged shell plates keep the unfolded silhouettes distinct. Generator revision 2 gives the rolled forms separate closed contours: shoulder petals, twisting iris blades, paired clamshell masses and recessed longitudinal ribs. Surface normals follow these actual volumes. Localized hinges and retracted gear replace the shared bright latitude belt; curved facial marks follow each shell. Every part remains inside the same unit radius.

The runtime pack uses canonical `defineEntity`/`definePack` and provides `body/rollable-robot@1.0.0`. Its custom bone tree is posed by KEEL `poseSkeleton`; `robotSkin` returns actual explicit entity capsules/boxes. It does not claim standard humanoid/quadruped clips. `createRobotDesign` produces rolled, portrait and unfolded meshes from the identical resolved genome and material roles. Rolled geometry is centered at the origin and every vertex fits a unit sphere; a gameplay consumer must scale it to the actual canonical radius and retain authoritative center/layer/elevation/transport visibility.

`robotPrototypeFoldMesh` is a pure art preview. No zone exists here, so it cannot authorize unfolding a live ordinary ball. Rendering has no random draws, wall-clock identity changes or rolling accumulator. The portrait and folded marks use the same face, shell, livery, palette and gear identity. True travel-matched rolling, gameplay/session binding, qualified rare transition zones, enemies and native pixel readability remain pending.

Tests cover independent pins, exact JSON regeneration, canonical entity bones/skins, all rolled sphere bounds, outward shell winding, finite/idempotent fold poses, and an additional family. These checks establish source readiness, not portrait/gameplay art acceptance.

The separate native preview tool captures the real KEEL mesh pass and source bytes for portrait, unfolded and rolled forms, including 8 logical-pixel rolled diagnostics. The revision 2 comparison pins the same palette and livery across all families, with additional 12 pixel three-quarter shell views and actual G-buffer silhouette masks. Those previews are not gameplay screenshots. Live ball integration, owner/team contrast, actual ramp tracking, rare qualified unfolding and visual acceptance remain open.
