This renderer presents actual indexed pixel art provided by a seeded scene generator. It does not convert the rejected 3D slab into a pixel filter.

Call `setWorld`, then `update` for **each native simulation frame**, then `render` at the display cadence. The provider receives the current frame and deterministic mechanism feedback, and must return matching `worldSha256` and `tick`. Call `reset` before a replay seek or restarting the same world. Returned sound cues can be consumed by the existing audio system; rendering itself never plays sounds or changes simulation state.

The art provider owns scene composition, source-bound mechanism sprites and static caching. It receives the existing viewport dimensions so it can choose a landscape or portrait logical profile. The presenter immediately consumes its indexed buffer, allowing the provider to reuse it. Palette conversion is exact and bounded. The view changes canvas backing dimensions only; it preserves existing CSS layout and controls. It replicates logical pixels at an integer backing pixel scale whenever they fit. A smaller backing viewport uses nearest downsampling, reported in stats. Large/high-DPI viewports automatically reduce backing resolution to 16 megapixels and 8192 pixels per edge; requested and effective pixel ratios remain visible in stats. Keep `image-rendering:pixelated` on the existing canvas for crisp CSS scaling.

This module is presentation infrastructure, not visual approval or complete game delivery. A rich scene, native browser checks, input integration and device acceptance remain separate requirements.

Set `PixelViewOptions.scaling` to `'nearest-fit'` to use the largest uniform scale that fits the bounded backing viewport. It keeps nearest sampling and the logical aspect ratio, including fractional destination dimensions; it does not stretch the world axes. Omitted scaling or `'integer'` retains the existing integer replication behavior. `fitPixelViewport(width, height, logicalWidth, logicalHeight, dpr, scaling)` exposes the same fit to camera and safe-inset calculations. Use the same scaling mode for those calculations and the view so their pixel-to-CSS scale agrees. `integerScale` reports whether the resulting scale replicates whole backing pixels.

Logical surfaces permit axes up to 2,048 pixels while retaining the existing maximum area of 1,048,576 pixels and the host's stricter `maxPixels`. This allows long portrait frames such as 320×1,312 within a 491,520-pixel host budget. Canvas backing limits, uniform nearest scaling and authority-frame identity checks are unchanged.
