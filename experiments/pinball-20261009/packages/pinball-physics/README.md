# KEEL pinball physics 0.1.0

Narrow `@keel-engine/pinball-physics` and `/runtime` exports instantiate a freestanding C17 WebAssembly kernel. The bundled TypeScript Uint8Array and independent `kernel/pinball.wasm` are exactly the same bytes; the exported SHA-256 and compiler string identify them. No DOM, renderer, clock, random number generator, fetch, or native host imports occur in the physics path. Each instance has fixed 128 KiB WASM memory. Browser qualification is performed by the integrating application; the module's Node test alone does not claim cross-browser execution evidence.

`createPinballPhysics(map)` exposes `step(inputBits)`, `readFrame()`, `readEvents()`, `setBall(placement)`, `snapshot()`, and `restore(bytes)`. Step always advances one 120 Hz tick. LEFT=1, RIGHT=2, LAUNCH=4, RESTART=8; physics uses left/right while world owns launch/restart edges. Public positions and velocities are table units and table units/tick; positive y points down. Internal coordinates/velocities are Q10 integers. Angles are integer tenths of a degree, from a committed Q10 trigonometric table.

## Contact model and bounds

This first classic kernel admits one ball, 128 zero-thickness segment rails, 32 circular bumpers and eight moving capsule flippers. Ball radius is 4–32 units, capsule radius 2–24, capsule length 16–160, map extent up to 2048 units. Maximum ball speed is 24 units/tick; active angular travel is 7 degrees/tick, return travel 4.5. Every tick divides both ball movement and flipper rotation into 64 bounded subdivisions. Each subdivision checks the entire ball path against capsule/rail geometry, including closest endpoint approach and a Q16 binary search for entry, so arbitrarily narrow grazing contacts are not lost between samples. A rotating capsule checks the conservative swept envelope of its previous/current axes and moving tip, with a two-Q10-quantum allowance for rotational arc curvature. This is conservative swept-envelope CCD, not exact analytic rotational earliest-time-of-impact CCD; it can respond early within the bounded substep envelope. Collider ties use sorted stable IDs within rails, bumpers, and flippers, in that group order.

Each subdivision iterates at most eight contact passes. On exhaustion the ball returns to its previous safe position, velocity is zeroed, mechanics stop at the previous substep, and `contact-budget` is emitted. Qualification must reject routine budget exhaustion; it is not hidden tunneling. Surface velocity uses actual rotating capsule motion, and reflection is relative to that surface. Holding a flipper permits an ordinary gravity/resting contact catch; there is no scripted upward teleport. Restitution and bumper impulse are bounded. Spin, surface friction, ball-to-ball contacts, one-way gates, ramps, and multiball are not implemented by this first kernel.

Snapshots bind the entire canonical map string, kernel SHA-256, version, all integer state (including integration remainders, contact cooldowns, actuator positions and event buffers), and exposed events. Restore validates before writing. Snapshot bytes are canonical UTF-8 JSON, convenient for existing KEEL binary resources; they are larger than an optimized network codec. Replays must pin the map, kernel and world/rules version. Scores are generated by the separate world module. Owner and layer IDs are admitted and applied now; their presence is not a claim that multiplayer or cross-field transfers exist.

## Build and checks

Run `node kernel/build.mjs` from this package or provide `PINBALL_CLANG` pointing at the same clang toolchain. The checked-in artifact was compiled using Homebrew Emscripten 6.0.5 `wasm32-clang` (`clang version 24.0.0git`). The script records exact bytes and digest; changing compilers requires digest/replay requalification. It intentionally does not install a compiler. Node/browser execute the artifact, not separately compiled native C.

From the engine root:

```
node --test packages/pinball-physics/test/*.test.ts packages/pinball-world/test/*.test.ts
node packages/pinball-physics/tools/probe-table.ts /absolute/path/to/table.ts
```

The probe consumes the real authored EMBERLINE map, drives only legal input bits, records upper-field returns after flips, and repeats all runs to compare transcript hashes. Module manifests follow the engine prepare/build pipeline. Local integration and a reproducible module build do not publish resources or prove selected-chain receipt/read-back.
